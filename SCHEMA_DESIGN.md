# Production Database Schema Design (Operational & Raw Data)

**Objective**:
1.  **Operational Persistence**: Store Users, Kite Sessions, Trading Schedules, and Trade History.
2.  **Raw Market Data**: Persist high-frequency L2 depth (valid for ML training).
3.  **Fundamental Data**: Persist daily reports (valid for ML training).

**Database**: PostgreSQL 15+.

---

## 1. Operational Schema (User & Trading)

### A. `users`
System users and settings.

```sql
CREATE TABLE users (
    user_id         BIGSERIAL PRIMARY KEY,
    username        TEXT NOT NULL UNIQUE,
    display_name    TEXT NOT NULL,
    logging_enabled BOOLEAN DEFAULT TRUE,
    created_at      TIMESTAMPTZ DEFAULT NOW(),
    
    -- Holdings stored as simplistic JSON array or separate table
    -- For Postgres, a JSONB array of strings is simplest: ["INFY", "RELIANCE"]
    holdings        JSONB DEFAULT '[]'::jsonb
);
```

### B. `kite_sessions`
Persist the Kite Connect session data (replacing JSON file).

```sql
CREATE TABLE kite_sessions (
    session_id      TEXT PRIMARY KEY,       -- e.g. "user123_2025-01-01"
    user_id         BIGINT REFERENCES users(user_id),
    
    api_key         TEXT NOT NULL,
    access_token    TEXT,
    public_token    TEXT,
    login_time      TIMESTAMPTZ,
    expires_at      TIMESTAMPTZ,            -- Usually next morning 06:00 AM
    is_active       BOOLEAN DEFAULT TRUE,
    
    updated_at      TIMESTAMPTZ DEFAULT NOW()
);
```

### C. `trading_schedules`
The "Plan" for future trades.

```sql
CREATE TABLE trading_schedules (
    schedule_id     BIGSERIAL PRIMARY KEY,
    user_id         BIGINT REFERENCES users(user_id),
    
    symbol          TEXT NOT NULL,
    instrument_token TEXT NOT NULL,
    
    side            TEXT NOT NULL CHECK (side IN ('BUY', 'SELL')),
    quantity        INTEGER NOT NULL,
    status          TEXT DEFAULT 'DRAFT',   -- DRAFT, SCHEDULED, EXECUTED, FAILED
    
    -- Schedule Parameters
    trade_date      DATE NOT NULL,
    session_slot    TEXT,                   -- MORNING_OPEN, PRE_CLOSE, etc.
    next_execution  TIMESTAMPTZ,
    limit_price     DOUBLE PRECISION,
    
    -- Settings
    auto_repeat     BOOLEAN DEFAULT FALSE,
    cancel_open_orders BOOLEAN DEFAULT TRUE,
    
    -- Feedback
    last_executed_at TIMESTAMPTZ,
    last_message    TEXT,
    
    created_at      TIMESTAMPTZ DEFAULT NOW(),
    updated_at      TIMESTAMPTZ DEFAULT NOW()
);
```

### D. `executed_trades`
The "History" of what actually happened. Only successful or attempted executions.

```sql
CREATE TABLE executed_trades (
    trade_id        UUID PRIMARY KEY,       -- Generated by app
    schedule_id     BIGINT REFERENCES trading_schedules(schedule_id),
    user_id         BIGINT REFERENCES users(user_id),
    
    symbol          TEXT NOT NULL,
    side            TEXT NOT NULL,
    
    -- Execution Details
    filled_qty      INTEGER,
    filled_price    DOUBLE PRECISION,       -- Avg Price
    exchange_order_id TEXT,
    
    execution_time  TIMESTAMPTZ DEFAULT NOW(),
    status          TEXT,                   -- SUCCESS, PARTIAL, REJECTED
    remarks         TEXT                    -- Any error message or note
);
```

## 3. Fundamental Data (Normalized)

Split for aggregation efficiency.

### A. `daily_quotes`
```sql
CREATE TABLE daily_quotes (
    report_date     DATE NOT NULL,
    token           BIGINT,
    symbol          TEXT,                   -- Denormalized for ease if token missing
    current_price   DOUBLE PRECISION,
    high_price      DOUBLE PRECISION,
    low_price       DOUBLE PRECISION,
    volume          BIGINT,
    market_cap      DOUBLE PRECISION,
    CONSTRAINT pk_daily_quotes PRIMARY KEY (report_date, symbol)
) PARTITION BY RANGE (report_date);
```

### B. `daily_valuations`
P/E, Ratios.
```sql
CREATE TABLE daily_valuations (
    report_date     DATE NOT NULL,
    symbol          TEXT,
    pe_ratio        DOUBLE PRECISION,
    book_value      DOUBLE PRECISION,
    dividend_yield  DOUBLE PRECISION,
    roce            DOUBLE PRECISION,
    roe             DOUBLE PRECISION,
    debt_to_equity  DOUBLE PRECISION,
    piotroski_score DOUBLE PRECISION,
    qtr_sales_var   DOUBLE PRECISION,
    qtr_profit_var  DOUBLE PRECISION,
    CONSTRAINT pk_daily_valuations PRIMARY KEY (report_date, symbol)
) PARTITION BY RANGE (report_date);
```

### C. `shareholding_patterns`
```sql
CREATE TABLE shareholding_patterns (
    report_date     DATE NOT NULL,
    symbol          TEXT,
    promoter_pct    DOUBLE PRECISION,
    public_pct      DOUBLE PRECISION,
    pledged_pct     DOUBLE PRECISION,
    change_prom_hold DOUBLE PRECISION,
    CONSTRAINT pk_shareholding PRIMARY KEY (report_date, symbol)
) PARTITION BY RANGE (report_date);
```

### D. `technical_indicators`
```sql
CREATE TABLE technical_indicators (
    report_date     DATE NOT NULL,
    symbol          TEXT,
    dma_50          DOUBLE PRECISION,
    dma_200         DOUBLE PRECISION,
    avg_vol_1wk     BIGINT,
    avg_vol_1mth    BIGINT,
    return_1d       DOUBLE PRECISION,
    return_1wk      DOUBLE PRECISION,
    CONSTRAINT pk_technicals PRIMARY KEY (report_date, symbol)
) PARTITION BY RANGE (report_date);
```

## 4. High-Frequency Market Data

### `market_snapshots` (Raw Depth)
**Partitioned by Day**.

```sql
CREATE TABLE market_snapshots (
    captured_at     TIMESTAMPTZ NOT NULL,
    token           BIGINT NOT NULL,
    symbol          TEXT NOT NULL,
    
    ltp             DOUBLE PRECISION,
    ltq             BIGINT,
    ltt             TEXT,
    volume          BIGINT,
    
    open_price      DOUBLE PRECISION,
    high_price      DOUBLE PRECISION,
    low_price       DOUBLE PRECISION,
    prev_close      DOUBLE PRECISION,
    lower_circuit   DOUBLE PRECISION,
    upper_circuit   DOUBLE PRECISION,
    
    -- JSONB: [[price, qty, ord], ...]
    bids            JSONB,
    asks            JSONB,
    
    CONSTRAINT pk_market_snapshots PRIMARY KEY (captured_at, token)
) PARTITION BY RANGE (captured_at);
```
